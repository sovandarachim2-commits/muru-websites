# Cloudflare R2 images

Add the `r2` block from `config.example.php` to `config.local.php`. Set `enabled` to `true`, and supply the Cloudflare account ID, bucket name, R2 S3 access key ID, secret access key and public URL. Values may be set directly in the private local config or through the environment variables shown in the example.

Create an R2 API token with Object Read & Write access scoped to the image bucket. Use its S3 credentials, not a general Cloudflare API token. Enable a custom domain on the bucket and use its HTTPS URL as `public_url`; the R2 development public URL also works for testing. Do not use the S3 API endpoint as the public image URL.

PHP requires cURL with `CURLOPT_AWS_SIGV4` support. Admin uploads go through the authenticated backend and require CSRF verification and an image-editing permission. Only valid JPG, PNG and WebP images up to 2 MB are accepted. Browser-to-R2 CORS is unnecessary because PHP sends the upload.

Existing Base64 images remain unchanged. New file uploads require R2 to be enabled; failures are shown in the editor. Save the product, category or website after upload to persist its URL. Removing a photo or cancelling an editor does not delete its R2 object.
